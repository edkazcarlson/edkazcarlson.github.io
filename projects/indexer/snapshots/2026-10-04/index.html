01 / INDEXER

DEVELOPMENT SNAPSHOT · OCTOBER 4, 2026

A closer look at
your image library.

A Windows file browser built around the way you remember images: what’s in them, what looks alike, and what you want to keep.

Indexer is an independent project by Edward Kazuya Carlson. It combines local AI retrieval with visual exploration and practical file tools, keeping the search result connected to the file itself.

01 / FIND

Search for the idea.
Refine the intent.

Filenames are only one clue. Indexer combines semantic image matches, recognized text, and paths in a ranked result list. Queries update as you type, with folder scope and negative terms available in the same search field.

Meaning, text, and filenames

Search space and images of a galaxy, rocket, and astronaut rise together. Local image embeddings, OCR, and path matching contribute to one fused ranking.

02 / EXPLORE

See the collection
as a landscape.

A similarity map gives a folder another way to be browsed. Related image embeddings become neighboring points, with thumbnail stacks and a companion gallery. A group board offers a compact overview of the same collection.

Map + grid

Pan, zoom, filter, preview, and select an area. Identical content shares a map stack with a copy-count badge; each file path remains available in the gallery.

14 files · 7 unique content stacks · actual embeddings

A board of visual groups

Switch between Map, Group board, and Expand map. Broad, Balanced, and Fine grouping presets keep the map coordinates steady, and selections carry across views.

The same collection in Group board view

Designed for bigger collections.

The separate 50,000-file synthetic test shows multiple groups. Virtualized galleries, viewport culling, a bounded thumbnail atlas, and cached layouts keep the browsing surface manageable.

Synthetic images and vectors demonstrate scale and UI behavior. They do not establish real-photo clustering quality.

03 / KEEP

Turn a result
into a useful decision.

Finding a file is the beginning of the workflow. Exact-duplicate review groups byte-identical files, reports reclaimable space, and gives mirrored folders a shared keeper decision.

01 / REVIEW

See copies together

Compare grouped results and choose which folder or copy to keep. The scan itself does not remove files.

02 / SELECT

Resolve the folder pair

Select redundant copies consistently across mirrored folders. Folder-level decisions help avoid leaving both trees fragmented.

03 / ACT

Recycle or merge

Delete redundant copies through the Recycle Bin, or preview a folder-pair merge that preserves unique files and resolves collisions.

04 / THE THROUGH-LINE

Retrieval and file work,
in one place.

Indexer’s focus is the combination: an on-device search engine, an exploratory view of a collection, and explicit tools for working with the files that search finds.

Local by design

Image embeddings and OCR are computed on the device and stored in a local SQLite database. Image indexing and retrieval do not require uploading the library to a cloud search service.

Connected to the filesystem

Browse folders and ZIP contents, use tabs and panes, preview results, and navigate to a file’s containing folder inside Indexer.

Useful beyond search

Export a folder’s recognized text to CSV, review corrupt or unreadable images with reasons, and find exact copies without another inference pass.

Measurement context and current limits

The 14-file screenshot corpus contains seven public scikit-image examples and one identical copy of each. The captured warm space query displays 5 ms; space not:astronaut displays 18 ms. These are individual GUI observations, including warm caches, rather than a statistical benchmark or a cold-start claim.

The separate 50,000-file generated fixture contains 11,220 unique content stacks. Recorded timings: cold folder preparation 20.49 s, native cached reopening 0.54 s, GUI cached reopening 0.89 s, preset switching 29–33 ms, and draw p95 10 ms. The test machine ran Windows 11 with 24 logical CPUs and 31.1 GiB usable RAM. A synthetic 50,000-unique-vector pipeline test took 66.12 s. These are different workloads.

The similarity-map feature is a development implementation and has not been packaged or released by this snapshot. Qualification on an actual 8-core, 16-GiB baseline and real-photo clustering evaluation remain future work. Exact-duplicate cleanup is implemented; near-duplicate cleanup, automatic culling, and visual folder diff are not presented here as completed features.

Why publish this snapshot?

This is a record of an independently developed project, its implementation choices, and the workflows it already supports. As AI features expand across desktop software, the snapshot gives visitors something concrete to inspect: the working interface, its behavior, and the recorded development history.

The purpose is to document the work. It does not claim that another company copied Indexer, that these ideas are unique inventions, or that repository timestamps prove priority over any particular announcement.
